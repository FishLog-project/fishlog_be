## ✨ 프로젝트 소개

FishLog는 낚시를 중심으로 여행을 계획하는 사용자가 겪는

- 🗺 **흩어진 정보**: 낚시 포인트, 대상 어종, 날씨·물때, 주변 관광지를 각각 다른 곳에서 찾아야 하는 문제
- 🌊 **오늘 상황을 알기 어려움**: 지금 이 포인트의 낚시지수·파고·수온이 어떤지 바로 확인하기 어려운 문제
- 📷 **남지 않는 조과 기록**: 잡은 물고기가 사진첩에만 쌓이고, 어떤 종인지도 확실히 모르는 문제

이러한 문제를 해결하기 위해 만들어진 **낚시 레저 + 관광 통합 서비스**입니다.

- 전국 **낚시 스팟 92곳(해양 49 · 내륙 43)**의 대상 어종과 **실시간 낚시 예보**를 보여주고
- 스팟 반경의 **관광지·숙박·음식점과 당일 혼잡도**를 함께 제안하며
- 잡은 물고기 사진을 **자체 AI 모델로 판별**해 Top-3 후보를 보여주고
- 인증한 기록으로 **어종 도감을 채우고 랭킹으로 경쟁**합니다.

```
① 스팟 탐색 → ② 예보·대상 어종 확인 → ③ 주변 관광 → ④ AI 어종 판별 → ⑤ 도감 인증 → ⑥ 랭킹
```

## 📌 주요 기능

### 1️⃣ 회원 & 인증

- 이메일 인증코드(6자리, TTL 5분) 기반 **자체 회원가입**, BCrypt 비밀번호 저장
- **Access 30분 + Refresh 14일 JWT**, 재발급 시 Refresh를 교체하는 **토큰 회전(rotation)**과 Redis 대조로 탈취 토큰 차단
- 재전송 쿨다운 30초 · 시간당 5회 · 오입력 5회 무효화로 **인증코드 남용 방지**, 메일은 `@Async` 비동기 발송
- 비밀번호 재설정 시 기존 Refresh 토큰을 삭제해 **세션 강제 무효화**

### 2️⃣ 낚시 스팟 & 실시간 예보

- 공공데이터 **바다낚시지수 API**와 국립생태원 담수어류 조사로 만든 스팟·어종 시드(스팟 92곳 · 어종 24종 · 페어 552개)
- 해양 스팟은 **낚시지수·파고·수온·기온·유속·풍속·물때**를 상세 조회 시점에 실시간으로, 내륙 스팟은 하폭·유수폭·수심 실측값을 제공
- 예보는 **Redis 캐시**로 외부 호출을 줄이고, 외부 API가 실패해도 기본 정보는 200으로 내려주는 **장애 격리(graceful degradation)**
- 사용자/IP별 1일 1회 **비동기 조회수 집계**로 인기 스팟 Top 3 · 해양/내륙 추천 배너 제공, 스팟 찜 기능

### 3️⃣ 주변 관광 & 혼잡도

- 한국관광공사 **TourAPI**로 스팟 반경의 관광지·숙박·음식점을 실시간 프록시 조회
- **관광지 집중률 예측 API**로 관광지마다 **당일 예상 혼잡도**를 결합
- 혼잡도는 관광지에만, 시군구별 1회만 조회해 재사용 → 30건 목록도 **외부 호출 0~2회**로 처리

### 4️⃣ AI 어종 판별 & 도감 인증

- 사진을 **자체 CNN 모델 서버(FastAPI, 별도 EC2)**로 보내 **Top-3 어종 후보** 제시 (Top-1 81% · Top-3 90.7%)
- **분류(저장 없음) → 사용자 확정 → 인증(S3 + DB)**의 2단계로 나눠, 오분류가 도감에 박히지 않게 하고 모델 장애 시에도 직접 선택으로 인증 가능
- 원본 바이트 그대로 전달 · `RestClient` 빈 재사용(처리량 3.4건/s → 15건/s) · **5xx·타임아웃만 1회 재시도**
- 도감 24종 외 어종은 **수기 등록**으로 별도 도감에 기록, 인증 기록 단위 통합 조회

### 5️⃣ 어종 도감 & 랭킹

- 24종 어종 카탈로그(희귀도·제철·서식지·설명)와 도감 이미지·실루엣 **정적 서빙**
- 현재 월 기준 **계절별 추천 어종 배너**
- **도감 완성도 · 최대 어종 크기** 2종 랭킹, 공동 순위(1,1,3) 처리, 닉네임 일괄 조회로 **N+1 없이 집계**

### 6️⃣ 마이페이지

- 프로필 조회, 닉네임·비밀번호 변경, **S3 프로필 이미지 업로드**, 회원 탈퇴

## 🌟 서비스 포인트

1️⃣ **낚시와 관광을 한 화면에서**
- 스팟을 고르면
  → 오늘의 낚시 예보와 대상 어종을 확인하고
  → 주변 관광지와 당일 혼잡도까지 이어서 여행을 계획

2️⃣ **AI는 제안하고, 확정은 사용자가**
- 모델이 Top-3 후보를 제시하고
  → 사용자가 직접 골라 인증
  → 오분류가 기록에 남지 않고, **모델 서버가 멈춰도 인증 흐름은 유지**

3️⃣ **외부 의존성에 흔들리지 않는 설계**
- 예보·관광·혼잡도·AI 모두 외부 시스템이지만
  → 캐시·타임아웃·재시도·장애 격리로
  → **외부가 실패해도 핵심 응답은 항상 정상 반환**

## 🏗 아키텍처

| 흐름 | 경로 |
|---|---|
| **사용자 트래픽** | `App` → `Nginx(HTTPS · Certbot)` → `EC2(Docker Compose · Spring Boot 4.1 / Java 21)` → `MySQL 8.0` · `Redis 7` |
| **어종 판별** | 백엔드가 사진 원본을 보안그룹으로 막힌 `모델 EC2(FastAPI)`에 전달, Top-3 후보를 도감 어종과 매핑 |
| **미디어** | 인증 사진·프로필 이미지는 `S3`, 도감 이미지는 서버 정적 서빙(`/images/fish/**`) |
| **외부 API** | 바다낚시지수(예보, Redis 캐시) · TourAPI(주변 관광) · 관광지 집중률(혼잡도) |
| **설정 관리** | 환경변수·properties는 private 서브모듈 `be_config`로 분리 |
| **CI** | PR → GitHub Actions가 `Spotless` 코드 스타일 검사 후 서브모듈 포함 빌드 검증 |
| **CD** | `main` 머지 → Docker 이미지 빌드(`latest` + 커밋 SHA 이중 태그) → `Docker Hub` 푸시 → SCP로 compose 전송 → EC2에서 `pull` · `up` |
